Low-latency linear layers

Fewest XOR2 gates at a depth bound, and the smallest XOR2/XOR3 area, for your binary matrix. The search program of the paper, compiled to WebAssembly, runs on this page: nothing leaves your computer.

1. Matrix

One row per output, entries 0 or 1 separated by spaces (row j gives output yj, column c is input xc). The NIST / Boyar–Peralta format (number of matrices, then “rows columns” and the rows) also works; lines starting with # are comments. At most 64 inputs and 128 outputs. About

    
The search combines four stages: (1) beam search over the near-ties of the depth-bounded Boyar–Peralta forward
      search, (2) the backward splitting of Shi, Feng and Xu, (3) beam search over these splits, and (4) a large neighborhood
      search around the best circuit. Every circuit found is also merged into XOR2/XOR3 gates (a gate of fan-out one that
      is not an output is absorbed into the gate that uses it), and the smallest areas are kept, with the unit areas of
      HILL for the UMC 180 nm and STM 130 nm libraries (XOR2 3.00 and 3.33 GE, XOR3 4.67 and 4.66 GE).

    
The three budgets are those of the command-line tool of the repository (python3 slpd.py run --preset …),
      and the circuits are written in the same format, that of the NIST Circuit Complexity Project (XOR3 out a b c
      for a 3-input gate whose last two operands form the absorbed gate). The runs use the same program,
      src/dbs.cpp, and the same seeds. The random choices of a seed also depend on the C++ standard library
      (libc++ here, usually libstdc++ on Linux), so a run can give other circuits than the same run of slpd.py.
      Before a circuit is shown, this page checks it again, independently of the search program: it computes the matrix
      within the depth bound.
